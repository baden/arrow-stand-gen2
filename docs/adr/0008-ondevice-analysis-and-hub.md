# ADR-0008 — Аналіз на пристрої та спільне залізо для хаба

- **Статус:** accepted
- **Дата:** 2026-11-18
- **Пов'язані:** ADR-0002, ADR-0004, ADR-0007, NFR-01, NFR-05, NFR-06

## Контекст

Дві вимоги замовника:

1. **Весь аналіз влучання — на пристрої**, а не на хабі.
2. **Хаб теж має бути дешевим** — бажано на тому самому залізі: той самий
   процесор, той самий радіочіп, можливо те саме живлення, тільки на
   більшу ємність.

Це означає, що хаб і мішень — **два режими одного пристрою**.

## Рішення

### 1. Увесь аналіз — на пристрої (CH32V203F8U6)

Обґрунтування: CH32V203F8U6 має 64 KB Flash, 20 KB SRAM, 144 МГц,
одноциклове множення й апаратне ділення. Цього вистачає на повний
конвеєр обробки, включно з класифікацією.

**Конвеєр обробки (майбутня прошивка):**

| Етап | Що робиться | Ресурси |
|---|---|---|
| 1. Сенсор | SC7A20 у FIFO-режимі (32 зразки), threshold-detector → INT1 | 0 (всередині акселерометра) |
| 2. Захоплення | burst-читання FIFO (96 байт) по SPI | DMA, ~1 мс |
| 3. Ознаки | модуль \|a\|, пік, RMS, імпульс Σ\|a\|Δt, zero-crossings, час наростання, **час на рейлі (sat_samples)** | int32, буфер 32×3×2 B = 192 B |
| 4. Класифікація | дерево рішень / мала int8-MLP на ознаках | ~2–6 KB Flash, ~0.5 KB RAM |
| 5. Звіт | пакет 17 Б: клас, ознаки, прапорці, батарея | LoRa P2P, SF11 |

**Бюджет пам'яті:** драйвер SX1262 5–8 KB + протокол 1–2 KB + драйвер
SC7A20 1 KB + DSP/AI 3–6 KB + застосунок 2–3 KB = **12–20 KB з 64 KB**;
RAM: буфери DSP ~4 KB + стек 1 KB з 20 KB. Запас великий.

**Порядок робіт (важливо):** перша прошивка — не класифікатор, а
**логгер**: накопичувати відрізки удару в flash/USB. Класифікатор пишеться
після R-03 (профіль удару), інакше пороги будуть вигадані.

**Стійкість до насичення.** Удар стріли майже напевно перевищить ±16 g
акселерометра (ADR-0003). Тому ознаки мають бути **нормалізовані**
(0…255) і розраховані так, щоб працювати на **обрізаному** сигналі:
головні — «час на рейлі», «час наростання», «нахил пре-рейл»; амплітуда
— лише якщо сигнал не насичений (прапорець `saturated` у пакеті).
План вимірювань і критерії розгалуження —
`docs/research/impact-profile-plan.md`.

### 2. Хаб — те саме залізо, інший режим

| Блок | Мішень | Хаб |
|---|---|---|
| U1 SX1262IMLTRT | TX (SF11) | **RX** (4.6 мА) |
| U2 CH32V203F8U6 | sleep + wake по INT1 | завжди RX + USB FS |
| Y1 кристал 32 МГц | так | так |
| U4 LDO 3.3 В | так | так |
| U3 SC7A20 | так | **без** |
| U5 TP4056 + J2 LiPo | так | **без** (живлення від USB) |
| J1 SMA | так | так |
| + | — | **USB-C** (живлення + дані) |

Спільні компоненти: U1, U2, Y1, U4 — 4 з 5 ключових позицій. Обидва
пристрої використовують ту саму прошивкову кодову базу (спільний HAL,
спільний драйвер SX1262, спільний протокол пакета).

**Рішення щодо PCB:** дві PCB-варіанти з однієї схеми:

- **PCB-A «мішень»**: U1..U5, Y1, J1, J2, SW1 — без USB-C.
- **PCB-B «хаб»**: U1, U2, Y1, U4, J1, USB-C — DNP: U3, U5, J2, SW1.

Чому дві PCB, а не одна з jumper-ом: мінімум деталей на мішені (правило
«без деталей про запас») і USB-C на мішені коштує ~$0.10 + 6 площадок
без потреби. Хаб — **один** пристрій, тому його setup-fee не критичний.

> Хаб живиться від USB-C 5 В → LDO 3.3 В. CH32V203F8U6: VDD 2.4–3.6 В,
> USB FS PHY живлення 3.3 В. ME6211 (вхіде до 6 В) підходить.

**Формат USB — уточнення (2026-11-18).** У корпусі **CH32V203F8U6 (QFN-20)
немає виводів PA11/PA12**, тобто USB FS недоступний. Тому в ADR-0011 прийнято
**CH32V203C8U6 (QFN-48)** для обох пристроїв: USB з'являється в мішені й
в хабі, а платформа стає єдиною.

| Варіант хаба | MCU | Ціна @100 | Вихід даних |
|---|---|---|---|
| UART + USB-UART (CH340/CP2102 ~$0.30) | CH32V203F8U6 (QFN-20) | $0.3852 + $0.30 | UART → ПЗ |
| USB FS нативно | **CH32V203C8U6 (QFN-48)** | **$0.6037** | USB CDC → ПЗ |

Другий варіант коштує на $0.22 більше за MCU, але дає USB без окремого
перетворювача й ту саму прошивкову базу (U1/U2/Y1/U4 + драйвери).
Рішення — в ADR-0011.

## Наслідки

**Позитивні:**
- Один радіо-стек, один драйвер, один протокол — одна точка підтримки.
- Хаб коштує ~$2.5–3 (без батареї, без акселерометра).
- Відсутність «чорної коробки»: класифікація на пристрої, сирі дані
  можна перевірити в лабораторії.
- Немає залежності від хаба для прийняття рішень.

**Негативні / ризики:**
- Класифікатор на пристрої вимагає реальних даних (R-03) — без них
  пороги будуть довільними.
- USB FS + CDC на CH32V203 вимагає відповідного драйвера на стороні ПЗ.
- Дві PCB-варіанти → два BOM-и, два замовлення на складі (для хаба
  це неважливо: один пристрій).

**Що це змушує робити далі:**
- R-03: стенд профілю удару (обов'язково до написання класифікатора).
- Протокол пакета v2 (16 байт, з класом) — `docs/00-requirements.md` §8.
- ADR-0009 (окремий): PCB-A / PCB-B, точний USB-протокол хаба.
- Прошивка: спільний код для обох режимів, перемикач «мішень/хаб».

## Перевірка

- R-03: профіль удару виміряно, пороги класифікатора виведені з даних.
- Прошивка вміщається: Flash ≤ 38 KB, RAM ≤ 10 KB.
- Хаб приймає події і передає їх на ПЗ; затримка ≤ 500 мс.
- Час автономності мішені не гірший за NFR-08 (R-05).
