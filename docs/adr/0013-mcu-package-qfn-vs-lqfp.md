# ADR-0013 — Пакет MCU: QFN48X7 (C8U6) замість LQFP48 (C8T6)

- **Статус:** accepted (переглянуто 2026-11-18 після запиту замовника)
- **Дата:** 2026-11-18
- **Пов'язані:** ADR-0011, ADR-0007, `docs/cost/budget.md`

## Контекст

Замовник поставив під сумнів: у посиланні на LCSC — **CH32V203C8T6, LQFP-48(7×7)**,
а ми обрали **CH32V203C8U6, QFN-48(7×7)**. У даташиті для рядків «C6 / C8»
пакет зазначено як «LQFP48, QFN48X7» — неоднозначно.

## Розв'язання неоднозначності

Номенклатура WCH (CH32V203 DS0, Chapter 5 «Package and ordering information»):

```
CH32V203 C8 T 6   →  C8 = кристал (64 KB Flash / 20 KB SRAM)
                     T  = пакет LQFP48 (7×7 мм, крок 0.5 мм)
                     6  = температура −40…+85 °C
CH32V203 C8 U 6   →  U  = пакет QFN48X7 (7×7 мм, крок 0.5 мм)
```

**«C6 / C8» — це НЕ пакет, а варіант кристалу** (Flash/SRAM). Пакет задає
четвертий символ MPN: **T = LQFP, U = QFN**. Тому в даташиті й стоїть
«LQFP48, QFN48X7» — це два пакети одного кристалу.

### Кристал в обох варіантах ідентичний

| | C8T6 (LQFP-48) | C8U6 (QFN-48) |
|---|---|---|
| Flash / SRAM | 64 KB / 20 KB | 64 KB / 20 KB |
| Ядро | QingKe V4B, 144 МГц | QingKe V4B, 144 МГц |
| GPIO | 37 | 37 |
| USB FS / CAN / SPI / I2C | 2×USB, 1×CAN, 2×SPI, 2×I2C | те саме |
| Живлення | 2.4–3.6 В | те саме |

**Розведення виводів однакове.** У CH32V203 DS0 Table 3-1-1 «QFN20/LQFP32/QFN32/
LQFP48/QFN48X7 pin definitions» — **одна таблиця**, у якій номери пінів для
LQFP48 і QFN48X7 збігаються в кожному рядку (напр. VSSA = 8, PB2/BOOT1 = 20,
VDD_VIO_1 = 24, PA14 = 37 — однаково). Отже карта виводів, яку ми перевірили
для QFN48X7, **дійсна і для LQFP48**.

## Рішення

**Лишаємо CH32V203C8U6 (QFN-48).**

| Критерій | C8U6 (QFN-48) | C8T6 (LQFP-48) |
|---|---|---|
| Ціна @100 шт | **$0.6037** | $0.6554 (+$0.052) |
| Ціна @1000 шт | $0.4626 | $0.4672 |
| Сток (на 2026-11-18) | 912 | **5 112** |
| Розмір на платі | **7×7 мм** (EP 5.5 мм усередині) | ~9.2×9.2 мм (вивідки «крила» 0.5 мм) |
| Тепловідвід | **експонований пад** → краще на 144 МГц | без EP, гірше |
| Паяння вручну / ремонт | складно (0.5 мм, без вивідків) | **легко** |
| SMT на JLCPCB | підтримується (EP — стандартна практика) | підтримується |

Обґрунтування:
1. **Складання SMT** — рішення вже прийняте (ADR-0006/0010): JLCPCB ставить
   QFN-48 з EXP-падом штатно; ручна пайка не потрібна.
2. **Ціна** — на $0.052/шт дешевше (1.3 % пристрою).
3. **Розмір плати мішені** — мішень уже розрослася до ~45×50 мм через
   QFN-48; LQFP-48 з вивідками додав би ще ~2.2 мм з кожного боку.
4. **Тепло** — 144 МГц + EXP-пад.

## Як перейти на LQFP-48, якщо знадобиться

Це **дешева операція**: розведення виводів те саме, тож змінюється лише поле
`Footprint` у символі U2:

- `arrowstand:TQFN-48_L7.0-W7.0-P0.50-BL-EP5.5`
  → `Package_QFP:LQFP-48_7x7_0.5mm_P0.5mm`

Жодної зміни в `firmware/*/board.h`, у протоколі чи в дротах схеми. BOM:
`C6407762` → `C3001172` (+$0.05).

**Коли перемикати:**
- сток QFN-48 (912 шт) не покриває партію → LQFP-48 має 5 112 шт;
- планується ручна пайка або ремонт плат;
- JLCPCB не впорається з EP-падом на конкретній партії.

## Наслідки

**Позитивні:** дешевше, компактніше, краще散热, ризик нуль — обидва варіанти
одного кристалу з однаковим розведенням.

**Негативні:** сток 912 шт обмежує партію; ручна пайка складніша.

**Що змушує робити далі:**
- Зафіксувати сток C8U6 в `docs/cost/budget.md` (вже є в Known issues).
- Перед замовленням PCB перевірити в JLCPCB, що конкретний футпрінт
  `TQFN-48 ... EP5.5` проходить їхню збірку (або перейти на LQFP-48).

## Перевірка

- Розведення виводів у `board.h` збігається з Table 3-1-1 DS0 (стовпці LQFP48 і
  QFN48X7 збігаються).
- BOM: C6407762, $0.6037 @100.
